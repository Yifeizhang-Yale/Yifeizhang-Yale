# Work together

[← Profile](https://github.com/Yifeizhang-Yale) · [Projects](PROJECTS.md)

## Join a project

1. **Find the workspace.** Choose a project from the directory and read its README. For a private project, send me your GitHub username through our existing channel and accept the repository invitation.
2. **Choose a task.** Browse the project's Issues. Comment on a task before starting so we can agree on the scope and avoid duplicating work.
3. **Make a small change.** Follow the project's setup instructions, create a branch or fork, and make one focused contribution.
4. **Open a Pull Request.** Link the Issue, explain the change, and include the checks you ran. Use a draft PR if you want early feedback.
5. **Review and merge.** Discuss the change on the PR, address feedback, and merge when the agreed checks pass and the reviewer is satisfied.

An **Issue** is a task or problem to discuss. A **Pull Request** is a proposed code or documentation change that others can review before it joins the main version.

## Try the collaboration pilot

The [private workspace](https://github.com/Yifeizhang-Yale/collaboration-sandbox) contains a small Python example with fictional input, task and bug-report forms, a contribution guide, and automatic checks on Pull Requests.

Invited collaborators can start with an Issue labeled **good first issue**. If the repository shows 404, sign in using the account that received the invitation and confirm that you accepted it.

## Start a new project

Agree on a short project brief: the goal, the first milestone, who is participating, and who will review changes. Create a separate repository and choose its visibility and collaborators deliberately.

The pilot is also a repository template. Anyone with access can use **Use this template → Create a new repository** as a starting point. Follow its [new-project checklist](https://github.com/Yifeizhang-Yale/collaboration-sandbox/blob/main/docs/START_A_PROJECT.md) to replace the example with the project's own code and documentation.
